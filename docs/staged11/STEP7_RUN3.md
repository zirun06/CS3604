## 05 改动

- 默认每批最多 3 个叶子、12,000 源字符。发出前估算为 400 + 850 × 叶子数 + 300 × 步骤数 + 350 × 涉及实体数。多叶批次估算超过有效输出上限的 75% 时先拆。单叶无法再拆时保留原有的失败记录。用第 3 次已接受的 03 产物离线重算，24 个叶子形成 13 批，估算输出为 1550–5850 token。
- 每行输出一条可独立校验的 JSON 记录，包括叶子 ID、API 与模块关联，以及该叶子所需的新契约和约定。类型字符串、字段映射、单元素数组和 HTTP 响应元组会确定性展开。复杂约束仍可用完整 JSON Schema。模块只需提供直接读写，校验器从调用图推导总读写和反向调用者，然后仍用 validate_backend_design 检查整个接受图与逐叶、逐步义务。backend_apis.json 的消费结构保持一致。
- 截断时逐行解析，只提交完整且通过校验的叶子和依赖，再用未接受的叶子组装下一次请求。只有闭合的 API、缺少归属或依赖校验的记录不会单独提交。若无可保留记录，拆小批次；单叶失败如实归档。正常响应仍按批校验。检索默认每种匹配取 2 个候选并保留前向被调用模块，完整接受图继续校验共享更新。
- 05 的初次和纠错请求都要求 DeepSeek 非推理模式，避免整个正文预算被已知的纠错配置占用。若明确拒绝非推理参数，05 记录失败；选择 provider 模式的其他模型仍由提供方控制。忽略该配置的网关仍可能以推理占满输出，编译器会识别截断并执行恢复。05 的输出预留至少达到估算值（受有效上限约束），实现阶段最多要求至少有 1024 token 正文空间，避免以几乎空的上限发送。硬上限仍包括实际发生的推理 token。
